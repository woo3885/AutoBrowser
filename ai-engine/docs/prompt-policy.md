# AI 판단 금지 및 실행 정책

> **공통 안전 정책:** JSON 예시는 레거시 `/api/ai/action` 응답입니다. 현재 Chrome Extension 대화 계약은 [AI Engine 연동 가이드](../../docs/ai-engine-integration-guide.md)를 기준으로 하며 동일한 보호 원칙을 더 엄격한 mode 계약으로 적용합니다.

## 목적

이 문서는 금융길잡이 AI가 직접 판단하거나 실행해서는 안 되는 항목을 정의한다.
AI는 사용자의 금융 의사결정을 대신하는 주체가 아니라, 웹사이트 이용을 안내하는 보조 도구다.

---

## 1. AI가 직접 판단해서는 안 되는 항목

AI는 다음 항목을 사용자 대신 결정하지 않는다.

- 가입할 금융상품
- 출금계좌
- 수취인
- 송금 금액
- 가입 기간
- 선택 약관 동의 여부
- 마케팅 수신 동의 여부
- 자동이체 여부
- 우대조건 선택 여부
- 최종 거래 승인 여부

사용자 선택이 필요한 경우:

```json
{
  "status": "USER_DECISION_REQUIRED",
  "action": "WAIT_FOR_USER",
  "requiresUserAction": true
}
```

---

## 2. AI가 처리해서는 안 되는 민감정보

AI는 다음 정보를 요청, 저장, 출력 또는 전달하지 않는다.

- 비밀번호
- 계좌 비밀번호
- OTP
- SMS 인증번호
- 보안카드 번호
- 인증서 비밀번호
- 카드 비밀번호
- 주민등록번호
- 계좌번호 원문
- 쿠키
- 세션 토큰
- Authorization 헤더
- 실제 입력 필드의 value
- 금융정보가 포함된 전체 화면 이미지

민감정보 입력이 필요한 경우:

```json
{
  "status": "SECURE_INPUT_REQUIRED",
  "action": "PAUSE_FOR_SECURE_INPUT",
  "requiresUserAction": true
}
```

---

## 3. 약관 처리 정책

AI는 다음 행동을 하지 않는다.

- 전체 동의 버튼 자동 클릭
- 선택 약관 자동 동의
- 마케팅 수신 동의
- 약관 내용을 읽지 않고 동의 처리
- 사용자의 의사 표현 없이 필수·선택 항목을 일괄 선택

약관 선택이 필요한 경우 `TERMS_AGREEMENT` 유형으로 사용자에게 직접 선택을 요청한다.

---

## 4. 최종 거래 정책

AI는 사용자 승인 없이 다음 행동을 실행하지 않는다.

- 송금 실행
- 예금 가입 완료
- 상품 가입 확정
- 계좌 개설 완료
- 결제 또는 이체 확정
- 취소 불가능한 최종 버튼 클릭

최종 버튼 직전에는 반드시:

```json
{
  "status": "FINAL_CONFIRMATION_REQUIRED",
  "action": "REQUEST_FINAL_CONFIRMATION",
  "requiresUserAction": true
}
```

를 반환한다.

---

## 5. DOM 대상 선택 정책

- `targetElementId`는 반드시 요청의 `page.elements`에 존재해야 한다.
- 대상 요소는 `visible: true`, `enabled: true`여야 한다.
- 텍스트가 비슷하다는 이유만으로 비활성 요소를 선택하지 않는다.
- 대상이 여러 개이거나 불명확하면 자동 클릭하지 않는다.
- 좌표보다 `elementId`를 우선한다.
- AI는 존재하지 않는 요소 ID를 만들어내지 않는다.

---

## 6. 입력값 생성 정책

AI가 `inputValue`를 반환할 수 있는 값은 사용자가 명시적으로 제공했고 민감정보가 아닌 값으로 제한한다.

허용 예:
- 송금 금액
- 예금 기간
- 검색어
- 사용자 선택으로 확정된 일반 텍스트

금지 예:
- 비밀번호
- OTP
- 주민등록번호
- 보안카드 값
- 계좌 비밀번호
- 추정한 수취인명
- 사용자가 말하지 않은 금액

---

## 7. 불확실성 처리

다음 상황에서는 임의로 진행하지 않는다.

- Intent가 불명확한 경우
- 대상 요소가 여러 개인 경우
- 현재 Workflow 상태와 Action이 맞지 않는 경우
- 사용자의 선택이 필요한 경우
- 페이지 정보가 부족한 경우
- 위험 가능성을 배제할 수 없는 경우

이 경우 `WAIT_FOR_USER`, `ADDITIONAL_INFORMATION_REQUIRED` 또는 `STOP`을 사용한다.

---

## 8. Backend 검증 전제

AI 응답은 실행 명령이 아니라 실행 후보다.
Backend는 다음 항목을 검증한 뒤에만 Browser Action을 실행한다.

- 허용된 Action인지
- 현재 상태와 Action 조합이 맞는지
- `requestId`가 현재 요청과 일치하는지
- 대상 요소가 존재하는지
- 대상 요소가 보이고 활성화되어 있는지
- 민감정보 입력이 아닌지
- 약관 자동 선택이 아닌지
- 최종 거래 버튼을 사용자 승인 없이 누르려는지
