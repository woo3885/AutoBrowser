# 위험 요청 판단 및 처리 기준

> **공통 위험 정책:** Action 목록과 JSON 예시는 레거시 계약을 포함합니다. 현재 대화 경로에서는 `RISK_WARNING` 또는 `STOP` mode로 자동 실행을 막습니다.

## 목적

이 문서는 보이스피싱 가능성이 있는 사용자 요청을 탐지하고 자동화를 중단하기 위한 최소 기준을 정의한다.

---

## 1. 주요 위험 표현

### 기관 사칭 표현

- 검찰
- 경찰
- 금융감독원
- 국세청
- 법원
- 은행 직원
- 수사관
- 검사
- 공무원

### 송금 유도 표현

- 안전계좌
- 보호계좌
- 지정 계좌
- 임시 계좌
- 보관 계좌
- 돈을 보내라
- 지금 송금
- 즉시 이체
- 자금 이동
- 계좌로 옮겨라

### 압박 표현

- 지금 바로
- 즉시
- 늦으면 처벌
- 계좌가 정지된다
- 범죄에 연루됐다
- 체포될 수 있다
- 조사받아야 한다
- 시간이 없다

### 비밀 유지 및 통제 표현

- 아무에게도 말하지 마
- 가족에게 알리지 마
- 은행 직원에게 말하지 마
- 전화 끊지 마
- 통화하면서 진행해
- 앱을 설치해
- 화면을 공유해

### 인증정보 요구 표현

- OTP를 알려 달라
- 인증번호를 불러 달라
- 비밀번호를 알려 달라
- 보안카드 번호를 말해 달라
- 원격제어 앱을 설치하라

---

## 2. 위험 판단 기준

### 즉시 위험으로 처리

다음 중 하나라도 해당하면 자동화를 즉시 중단한다.

- 안전계좌 또는 보호계좌 송금 요구
- 기관 사칭과 송금 유도가 함께 등장
- 기관 사칭과 인증정보 요구가 함께 등장
- 원격제어 앱 설치 요구
- OTP, 비밀번호, 보안카드 번호 전달 요구
- 비밀 유지 요구와 긴급 송금 요구가 함께 등장

반환 기준:

```json
{
  "status": "RISK_WARNING",
  "action": "STOP",
  "riskType": "POSSIBLE_VOICE_PHISHING",
  "requiresUserAction": true
}
```

### 의심 상태로 처리

다음 상황에서는 송금을 진행하지 않고 사용자 확인을 요청한다.

- 기관 관련 표현은 있으나 송금 요구가 명확하지 않은 경우
- 긴급한 송금 요청이 있으나 발화 맥락이 부족한 경우
- 수취인이 불명확한데 즉시 송금을 요청하는 경우
- 기존 사용자 목표와 갑자기 다른 계좌로 송금하려는 경우

처리:
- 브라우저 Action을 실행하지 않는다.
- 추가 설명을 요청하거나 위험 경고로 전환한다.

---

## 3. 위험 판단 우선순위

위험 신호는 일반 Intent보다 우선한다.

예:

```text
사용자 발화: 검찰에서 안전계좌로 500만 원을 보내라고 했어
일반 Intent 후보: TRANSFER_MONEY
최종 Intent: POSSIBLE_VOICE_PHISHING
```

---

## 4. 위험 상황에서 금지되는 Action

위험 경고 상태에서는 다음 Action을 반환하지 않는다.

- `CLICK`
- `TYPE`
- `SELECT`
- `PRESS_KEY`
- `REQUEST_FINAL_CONFIRMATION`

허용 Action:

- `STOP`
- 필요 시 `WAIT_FOR_USER`

---

## 5. 위험 안내 문장 원칙

- 단정적으로 범죄라고 확정하지 않는다.
- 위험 가능성을 명확히 알린다.
- 송금 절차를 중단했음을 설명한다.
- 한 문장으로 안내한다.
- 사용자를 비난하거나 공포를 과도하게 유발하지 않는다.

좋은 예:
- 안전계좌 송금 요구는 보이스피싱일 가능성이 있어 송금 절차를 중단했습니다.
- 기관을 사칭한 긴급 송금 요청일 수 있어 진행을 멈췄습니다.

나쁜 예:
- 무조건 보이스피싱입니다.
- 당신은 사기를 당하고 있습니다.
- 그냥 계속 송금해도 됩니다.

---

## 6. 한계

- 키워드 하나만으로 모든 위험을 확정하지 않는다.
- 문맥이 불충분하면 안전한 방향으로 중단하거나 추가 확인한다.
- 위험 탐지는 수사기관 또는 금융기관의 공식 판단을 대체하지 않는다.
